# SMB 2.0/2.1 租赁协议规范

## 概述

SMB 2.0/2.1 租赁协议（Lease Protocol）是一种客户端缓存机制，允许客户端在本地缓存文件数据，同时与服务器保持一致性。租赁协议通过租赁令牌（Lease Token）和租赁键（Lease Key）来管理客户端的缓存权限。

## 租赁协议的基本概念

### 租赁（Lease）
租赁是服务器授予客户端的一种权限，允许客户端在特定条件下缓存文件数据。租赁具有以下特性：
- **时间限制**：租赁有明确的持续时间
- **条件限制**：租赁可能因特定条件而失效
- **可撤销性**：服务器可以随时撤销租赁

### 租赁令牌（Lease Token）
租赁令牌是一个唯一标识符，用于标识特定的租赁。它由服务器生成并返回给客户端，客户端在后续操作中使用此令牌来证明其租赁权限。

### 租赁键（Lease Key）
租赁键是一个128位的唯一标识符，用于在客户端和服务器之间建立租赁关系。它确保租赁的唯一性和安全性。

## 租赁类型

SMB 2.0/2.1 支持以下租赁类型：

### 1. 读取租赁（Read Lease）
- 允许客户端缓存文件数据进行读取
- 当其他客户端修改文件时，租赁失效
- 适用于只读访问场景

### 2. 写入租赁（Write Lease）
- 允许客户端缓存文件数据进行写入
- 提供独占写入权限
- 适用于单客户端写入场景

### 3. 句柄租赁（Handle Lease）
- 基于文件句柄的租赁
- 与特定的文件句柄绑定
- 句柄关闭时租赁自动失效

## 租赁协议的工作流程

### 1. 租赁请求
客户端通过 `SMB2_CREATE` 请求创建文件时，可以请求租赁：
- 在 `CreateContext` 中包含 `SMB2_CREATE_REQUEST_LEASE` 结构
- 指定所需的租赁类型和租赁键
- 服务器评估请求并决定是否授予租赁

### 2. 租赁授予
服务器在 `SMB2_CREATE` 响应中返回租赁信息：
- 在 `CreateContext` 中包含 `SMB2_CREATE_RESPONSE_LEASE` 结构
- 返回租赁令牌和租赁状态
- 指定租赁的持续时间和条件

### 3. 租赁维护
客户端需要定期维护租赁：
- 通过 `SMB2_LEASE_BREAK` 请求检查租赁状态
- 响应服务器的租赁中断通知
- 在租赁失效时清理本地缓存

### 4. 租赁中断
当租赁条件不再满足时，服务器会中断租赁：
- 发送 `SMB2_LEASE_BREAK` 通知
- 客户端必须响应并清理缓存
- 租赁中断后需要重新请求

## 租赁协议的数据结构

### SMB2_CREATE_REQUEST_LEASE
```c
typedef struct {
    UINT32 LeaseKey[4];           // 128位租赁键
    UINT32 LeaseState;            // 请求的租赁状态
    UINT32 LeaseFlags;            // 租赁标志
    UINT64 LeaseDuration;         // 租赁持续时间
} SMB2_CREATE_REQUEST_LEASE;
```

### SMB2_CREATE_RESPONSE_LEASE
```c
typedef struct {
    UINT32 LeaseKey[4];           // 128位租赁键
    UINT32 LeaseState;            // 授予的租赁状态
    UINT32 LeaseFlags;            // 租赁标志
    UINT64 LeaseDuration;         // 租赁持续时间
    UINT64 LeaseEpoch;            // 租赁纪元
} SMB2_CREATE_RESPONSE_LEASE;
```

## 租赁状态

### 租赁状态值
- `SMB2_LEASE_NONE` (0x00)：无租赁
- `SMB2_LEASE_READ_CACHING` (0x01)：读取缓存租赁
- `SMB2_LEASE_HANDLE_CACHING` (0x02)：句柄缓存租赁
- `SMB2_LEASE_WRITE_CACHING` (0x04)：写入缓存租赁

### 租赁标志
- `SMB2_LEASE_FLAG_BREAK_IN_PROGRESS` (0x02)：租赁中断进行中
- `SMB2_LEASE_FLAG_PARENT_LEASE_KEY_SET` (0x04)：父租赁键已设置

## 租赁协议的优势

### 1. 性能提升
- 减少网络传输
- 降低服务器负载
- 提高客户端响应速度

### 2. 一致性保证
- 确保缓存数据的一致性
- 防止数据冲突
- 支持多客户端环境

### 3. 灵活性
- 支持多种租赁类型
- 可配置的租赁持续时间
- 动态租赁管理

## 租赁协议的限制

### 1. 复杂性
- 增加了协议实现的复杂性
- 需要额外的状态管理
- 错误处理更加复杂

### 2. 兼容性
- 需要客户端和服务器都支持
- 可能存在版本兼容性问题
- 需要适当的降级机制

### 3. 资源消耗
- 需要额外的内存存储租赁信息
- 需要定期维护租赁状态
- 可能影响系统性能

## 最佳实践

### 1. 租赁管理
- 合理设置租赁持续时间
- 及时响应租赁中断通知
- 正确清理过期的租赁

### 2. 错误处理
- 处理租赁中断情况
- 实现租赁降级机制
- 提供适当的错误恢复

### 3. 性能优化
- 根据访问模式选择合适的租赁类型
- 避免不必要的租赁请求
- 优化租赁维护频率

## 安全考虑

### 1. 租赁键安全
- 使用加密安全的随机数生成租赁键
- 防止租赁键被猜测或重放
- 定期轮换租赁键

### 2. 访问控制
- 验证客户端的租赁权限
- 防止未授权的租赁使用
- 实现适当的审计日志

### 3. 数据保护
- 确保租赁中断时数据安全
- 防止缓存数据泄露
- 实现数据完整性检查

## 总结

SMB 2.0/2.1 租赁协议是一个强大的客户端缓存机制，通过租赁令牌和租赁键提供了高效、一致的文件访问方式。虽然增加了协议实现的复杂性，但其带来的性能提升和一致性保证使其成为现代文件共享系统的重要组成部分。

正确理解和实现租赁协议对于构建高性能、可靠的 SMB 服务器和客户端至关重要。开发者应该仔细考虑租赁类型的选择、错误处理机制以及安全考虑，以确保系统的稳定性和安全性。
