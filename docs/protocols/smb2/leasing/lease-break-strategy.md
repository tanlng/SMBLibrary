# SMB2 Lease 租约中断策略 (Lease Break Strategy) - 草稿

## 文档目的

本文档定义 SMB2 服务器在各种文件操作场景下，应该何时中断哪些客户端的租约（Lease）。租约中断是 SMB2 缓存一致性机制的核心，确保多客户端环境下的数据一致性。

---

## 核心原则

### 1. 本地缓存原则
- 持有租约的客户端可以在**本地缓存**文件数据、元数据和句柄
- 租约允许客户端推迟或批量处理文件操作，减少网络往返

### 2. 冲突检测原则
- 当**另一个客户端**的操作可能与**现有租约持有者**的缓存产生冲突时，服务器必须中断租约
- 租约中断强制客户端刷新缓存、释放锁，确保数据一致性

### 3. 租约类型
SMB2 定义三种租约权限（可组合）：
- **Read Caching (R)**: 0x01 - 缓存读取的数据
- **Handle Caching (H)**: 0x02 - 缓存文件句柄（避免重复 Open/Close）
- **Write Caching (W)**: 0x04 - 缓存写入的数据（延迟写回）

常见组合：
- `0x03` (RH): 只读文件，可缓存句柄
- `0x07` (RWH): 独占访问，可缓存读写和句柄
- `0x00`: 无租约

---

## 租约中断决策表

### 表格说明

- **操作发起者**：执行操作的客户端
- **租约持有者**：当前持有文件/目录租约的客户端
- **操作类型**：具体的文件系统操作
- **是否中断租约**：服务器是否需要发送 Lease Break Notification
- **中断目标**：需要中断哪个客户端的租约
- **新租约状态**：租约被中断后应降级到的状态

### 场景 1：单文件操作

| 操作发起者 | 租约持有者 | 持有租约 | 操作类型 | 是否中断 | 中断目标 | 新租约状态 | 是否中断父目录 | 原因说明 |
|-----------|-----------|---------|---------|---------|---------|-----------|---------------|---------|
| 客户端 A | 客户端 A | RH | A 读取文件 | ❌ 否 | - | - | ❌ 否 | 自己持有读租约，直接从缓存读取 |
| 客户端 A | 客户端 A | RWH | A 写入文件 | ❌ 否 | - | - | ❌ 否 | 自己持有写租约，可本地缓存写入 |
| 客户端 A | 客户端 A | RH | A 修改文件属性 | ❌ 否 | - | - | ❌ 否 | 元数据修改不影响数据缓存 |
| 客户端 A | 客户端 A | RWH | A 删除文件 | ❌ 否 | - | - | ❌ 否 | 自己的操作，租约在 Close 时自动释放 |
| **客户端 B** | **客户端 A** | **RH** | **B 读取文件** | **❌ 否** | **-** | **-** | **❌ 否** | **Read 租约允许共享读取** |
| **客户端 B** | **客户端 A** | **RWH** | **B 读取文件** | **✅ 是** | **客户端 A** | **RH** | **❌ 否** | **W 租约阻止其他客户端读取脏数据，必须降级到 RH** |
| **客户端 B** | **客户端 A** | **RH** | **B 写入文件** | **✅ 是** | **客户端 A** | **0x00** | **❌ 否** | **写入冲突，必须完全中断 A 的租约** |
| **客户端 B** | **客户端 A** | **RWH** | **B 写入文件** | **✅ 是** | **客户端 A** | **0x00** | **❌ 否** | **写入冲突，必须完全中断 A 的租约** |
| **客户端 B** | **客户端 A** | **RH** | **B 删除文件** | **✅ 是** | **客户端 A** | **0x00** | **✅ 是** | **删除操作，必须中断所有租约（含父目录）** |
| **客户端 B** | **客户端 A** | **RWH** | **B 重命名文件** | **✅ 是** | **客户端 A** | **0x00** | **✅ 是** | **重命名改变路径，必须中断所有租约（含父目录）** |
| 客户端 B | 客户端 A | RH | B 打开文件（只读） | ❌ 否 | - | - | ❌ 否 | Read 租约允许多个客户端只读访问 |
| 客户端 B | 客户端 A | RWH | B 打开文件（只读） | ✅ 是 | 客户端 A | RH | ❌ 否 | 降级为共享读租约 |
| 客户端 B | 客户端 A | RH | B 打开文件（读写） | ✅ 是 | 客户端 A | 0x00 | ❌ 否 | 需要写入权限，完全中断 |

### 场景 3：重命名操作的复杂性

重命名（Rename）操作涉及**多个资源**和**多种租约**，需要特别注意：

#### 3.1 重命名文件 `\dir\file.txt` → `\dir\newfile.txt`（同目录）

| 资源 | 租约持有者 | 持有租约 | 是否中断 | 中断顺序 | 新租约状态 | 是否中断父目录 | 原因说明 |
|------|-----------|---------|---------|---------|-----------|---------------|---------|
| **目标文件 `file.txt`** | 客户端 A | RH/RWH | ✅ 是 | **第 1 步** | 0x00 | **✅ 是** | 文件路径改变，旧句柄失效，必须先中断（含父目录） |
| **父目录 `\dir`** | 客户端 B | RH | ✅ 是 | 第 2 步 | 0x00 | **N/A (当前)** | NotifyChange + 中断父目录租约 (FILE_ACTION_RENAMED) |
| **父目录 `\dir`** | 客户端 B | RWH | ✅ 是 | 第 3 步 | 0x00 | **N/A (当前)** | W 租约必须中断，确保目录内容一致性 |

**时序建议（基于 Windows Server 行为）**：
```
1. Lease Break: 目标文件 file.txt (客户端 A)
2. 等待客户端 A 响应 (Close 或 Ack)
3. NotifyChange: 父目录 \dir (通知所有监听者)
4. Lease Break: 父目录 \dir (如果客户端 B 持有 W 租约)
```

#### 3.2 重命名目录 `\dir\subdir` → `\dir\newsubdir`

| 资源 | 租约持有者 | 持有租约 | 是否中断 | 中断顺序 | 新租约状态 | 是否中断父目录 | 原因说明 |
|------|-----------|---------|---------|---------|-----------|---------------|---------|
| **目标目录 `subdir`** | 客户端 A | RH/RWH | ✅ 是 | **第 1 步** | 0x00 | **✅ 是** | 目录路径改变，必须中断（含父目录） |
| **目录内的所有文件** | 任何客户端 | 任何租约 | ✅ 是 | 第 2 步 | 0x00 | **❌ 否** | 路径改变影响所有子资源 |
| **父目录 `\dir`** | 客户端 B | RH | ✅ 是 | 第 3 步 | 0x00 | **N/A (当前)** | NotifyChange + 中断父目录租约 |
| **父目录 `\dir`** | 客户端 B | RWH | ✅ 是 | 第 4 步 | 0x00 | **N/A (当前)** | W 租约必须中断，确保目录内容一致性 |

#### 3.3 移动文件 `\dir1\file.txt` → `\dir2\file.txt`（跨目录）

| 资源 | 租约持有者 | 持有租约 | 是否中断 | 中断顺序 | 新租约状态 | 是否中断父目录 | 原因说明 |
|------|-----------|---------|---------|---------|-----------|---------------|---------|
| **目标文件 `file.txt`** | 客户端 A | RH/RWH | ✅ 是 | **第 1 步** | 0x00 | **✅ 是 (源+目标)** | 路径改变，需中断源和目标父目录 |
| **源父目录 `\dir1`** | 客户端 B | RH | ✅ 是 | 第 2 步 | 0x00 | **N/A (当前)** | NotifyChange (FILE_ACTION_REMOVED) + 中断租约 |
| **源父目录 `\dir1`** | 客户端 B | RWH | ✅ 是 | 第 3 步 | 0x00 | **N/A (当前)** | 目录内容变化，必须中断 |
| **目标父目录 `\dir2`** | 客户端 C | RH | ✅ 是 | 第 4 步 | 0x00 | **N/A (当前)** | NotifyChange (FILE_ACTION_ADDED) + 中断租约 |
| **目标父目录 `\dir2`** | 客户端 C | RWH | ✅ 是 | 第 5 步 | 0x00 | **N/A (当前)** | 目录内容变化，必须中断 |

### 场景 4：删除操作

| 操作发起者 | 租约持有者 | 持有租约 | 操作类型 | 是否中断 | 中断目标 | 新租约状态 | 是否中断父目录 | 原因说明 |

## 实现建议

### 1. 租约中断的触发点

在 `SetInfoHelper.cs`, `NetworkFileStore.cs` 等关键操作入口，检查：
```csharp
// 伪代码
if (操作影响的资源 != 操作发起者持有的租约资源)
{
    // 查找所有持有该资源租约的其他客户端
    var affectedLeases = LeaseManager.GetLeasesForPath(targetPath);
    
    foreach (var lease in affectedLeases)
    {
        if (lease.ClientId != currentClientId)
        {
            // 根据操作类型决定新租约状态
            var newState = CalculateNewLeaseState(lease.CurrentState, operationType);
            LeaseManager.BreakLease(lease, newState);
        }
    }
}
```

### 2. 重命名操作的特殊处理

```csharp
// 重命名时的租约中断顺序
public void HandleRename(string oldPath, string newPath)
{
    // 步骤 1: 中断目标资源的租约（最高优先级）
    LeaseManager.BreakLeases(oldPath, newLeaseState: 0x00);
    
    // 步骤 2: 等待客户端响应（可选，但推荐）
    // await LeaseManager.WaitForBreakAcknowledgment(oldPath, timeout: 1000ms);
    
    // 步骤 3: 执行实际的重命名操作
    FileSystem.Rename(oldPath, newPath);
    
    // 步骤 4: 发送 NotifyChange 通知
    var parentDir = Path.GetDirectoryName(oldPath);
    NotifyChangeProcessor.NotifyRename(parentDir, oldName, newName);
    
    // 步骤 5: 中断父目录的写租约（如果存在）
    LeaseManager.BreakWriteLeases(parentDir, newLeaseState: 0x01); // 降级到 R
}
```

### 3. 租约状态计算逻辑

```csharp
private LeaseState CalculateNewLeaseState(LeaseState current, OperationType operation)
{
    return operation switch
    {
        OperationType.Read when current.HasFlag(LeaseState.Write) 
            => LeaseState.Read | LeaseState.Handle, // RWH → RH
        
        OperationType.Write 
            => LeaseState.None, // 任何写操作都完全中断
        
        OperationType.Delete 
            => LeaseState.None, // 删除操作完全中断
        
        OperationType.Rename 
            => LeaseState.None, // 重命名完全中断
        
        OperationType.SetInfo when current.HasFlag(LeaseState.Write) 
            => LeaseState.Read | LeaseState.Handle, // 元数据修改降级
        
        _ => current // 默认保持不变
    };
}
```

## 特殊注意事项

### ⚠️ 1. NotifyChange 不是租约中断的替代品
- **NotifyChange** 用于通知客户端**目录内容变化**
- **Lease Break** 用于强制客户端**刷新缓存**
- 两者必须**配合使用**，但**触发时机不同**

### ⚠️ 2. 租约中断的时序很重要
根据 Windows Server 的行为（基于报文分析）：
1. **重命名/删除**：先中断目标资源租约 → 发送 NotifyChange → 中断父目录租约
2. **创建文件/子目录**：先中断**父目录**租约（如果其他客户端持有）→ 发送 NotifyChange
3. **修改文件**：先中断文件租约（如果其他客户端持有）→ 发送 NotifyChange

**重要发现（基于 Windows Server 实测）**：
- 创建 `\A\file.txt` 时，会中断 `\A` 目录的租约（即使是 Read 租约）
- 创建 `\A\subdir` 时，会中断 `\A` 目录的租约
- 这确保了持有父目录租约的客户端能感知到目录内容变化

### ⚠️ 3. Handle Caching 的特殊性
- **H** 租约允许客户端保持句柄打开，即使暂时不使用
- 重命名操作必须中断 **H** 租约，因为路径改变导致句柄失效
- 删除操作也必须中断 **H** 租约

### ⚠️ 4. 租约的作用域
- 租约是**按文件/目录**粒度持有的
- 一个客户端可以同时持有**多个文件**的租约
- 重命名父目录时，需要递归中断**所有子资源**的租约
