# SMB 2.0/2.1 租约协议规范

## 概述

SMB 2.0/2.1 租约协议（Lease Protocol）是一种客户端缓存机制，允许客户端在本地缓存文件数据，同时与服务器保持一致性。租约协议通过租约令牌（Lease Token）和租约键（Lease Key）来管理客户端的缓存权限。

## 租约协议的基本概念

### 租约（Lease）
租约是服务器授予客户端的一种权限，允许客户端在特定条件下缓存文件数据。租约具有以下特性：
- **时间限制**：租约有明确的持续时间
- **条件限制**：租约可能因特定条件而失效
- **可撤销性**：服务器可以随时撤销租约

### 租约令牌（Lease Token）
租约令牌是一个唯一标识符，用于标识特定的租约。它由客户端生成并在请求中发送给服务器，服务器使用此令牌来管理租约。

### 租约键（Lease Key）
租约键是一个128位的唯一标识符（GUID），由**客户端**生成，用于在客户端和服务器之间建立租约关系。它确保租约的唯一性和安全性。

**重要**：根据 Wireshark 抓包验证，LeaseKey 由客户端生成，而不是服务器生成。

## 租约类型

SMB 2.0/2.1 支持以下租约类型：

### 1. 读取租约（Read Lease）
- 允许客户端缓存文件数据进行读取
- 当其他客户端修改文件时，租约失效
- 适用于只读访问场景

### 2. 写入租约（Write Lease）
- 允许客户端缓存文件数据进行写入
- 提供独占写入权限
- 适用于单客户端写入场景

### 3. 句柄租约（Handle Lease）
- 基于文件句柄的租约
- 与特定的文件句柄绑定
- 句柄关闭时租约自动失效

## 租约协议的工作流程

### 1. 租约请求
客户端通过 `SMB2_CREATE` 请求创建文件时，可以请求租约：
- 在 `CreateContext` 中包含 `SMB2_CREATE_REQUEST_LEASE` 结构
- 指定所需的租约类型和租约键（由客户端生成）
- 服务器评估请求并决定是否授予租约

### 2. 租约授予
服务器在 `SMB2_CREATE` 响应中返回租约信息：
- 在 `CreateContext` 中包含 `SMB2_CREATE_RESPONSE_LEASE` 结构
- 返回租约状态（可能降级）
- 使用客户端提供的租约键

### 3. 租约维护
客户端需要定期维护租约：
- 通过 `SMB2_LEASE_BREAK` 请求检查租约状态
- 响应服务器的租约中断通知
- 在租约失效时清理本地缓存

### 4. 租约中断
当租约条件不再满足时，服务器会中断租约：
- 发送 `SMB2_LEASE_BREAK` 通知
- 客户端必须响应并清理缓存
- 租约中断后需要重新请求

## 租约协议的数据结构

### SMB2_CREATE_REQUEST_LEASE
```c
typedef struct {
    UINT32 LeaseKey[4];           // 128位租约键（由客户端生成）
    UINT32 LeaseState;            // 请求的租约状态
    UINT32 LeaseFlags;            // 租约标志
    UINT64 LeaseDuration;         // 租约持续时间
} SMB2_CREATE_REQUEST_LEASE;
```

### SMB2_CREATE_RESPONSE_LEASE
```c
typedef struct {
    UINT32 LeaseKey[4];           // 128位租约键（与客户端相同）
    UINT32 LeaseState;            // 授予的租约状态
    UINT32 LeaseFlags;            // 租约标志
    UINT64 LeaseDuration;         // 租约持续时间
    UINT64 LeaseEpoch;            // 租约纪元（版本号）
} SMB2_CREATE_RESPONSE_LEASE;
```

## 租约状态

### 租约状态值
- `SMB2_LEASE_NONE` (0x00)：无租约
- `SMB2_LEASE_READ_CACHING` (0x01)：读取缓存租约
- `SMB2_LEASE_HANDLE_CACHING` (0x02)：句柄缓存租约
- `SMB2_LEASE_WRITE_CACHING` (0x04)：写入缓存租约

### 租约标志
- `SMB2_LEASE_FLAG_BREAK_IN_PROGRESS` (0x02)：租约中断进行中
- `SMB2_LEASE_FLAG_PARENT_LEASE_KEY_SET` (0x04)：父租约键已设置

## 租约协议的优势

### 1. 性能提升
- 减少网络传输
- 降低服务器负载
- 提高客户端响应速度

### 2. 一致性保证
- 确保缓存数据的一致性
- 防止数据冲突
- 支持多客户端环境

### 3. 灵活性
- 支持多种租约类型
- 可配置的租约持续时间
- 动态租约管理

## 租约协议的限制

### 1. 复杂性
- 增加了协议实现的复杂性
- 需要额外的状态管理
- 错误处理更加复杂

### 2. 兼容性
- 需要客户端和服务器都支持
- 可能存在版本兼容性问题
- 需要适当的降级机制

### 3. 资源消耗
- 需要额外的内存存储租约信息
- 需要定期维护租约状态
- 可能影响系统性能

## 最佳实践

### 1. 租约管理
- 合理设置租约持续时间
- 及时响应租约中断通知
- 正确清理过期的租约

### 2. 错误处理
- 处理租约中断情况
- 实现租约降级机制
- 提供适当的错误恢复

### 3. 性能优化
- 根据访问模式选择合适的租约类型
- 避免不必要的租约请求
- 优化租约维护频率

## 安全考虑

### 1. 租约键安全
- 使用加密安全的随机数生成租约键（客户端生成）
- 防止租约键被猜测或重放
- 定期轮换租约键

### 2. 访问控制
- 验证客户端的租约权限
- 防止未授权的租约使用
- 实现适当的审计日志

### 3. 数据保护
- 确保租约中断时数据安全
- 防止缓存数据泄露
- 实现数据完整性检查

## 总结

SMB 2.0/2.1 租约协议是一个强大的客户端缓存机制，通过租约令牌和租约键提供了高效、一致的文件访问方式。虽然增加了协议实现的复杂性，但其带来的性能提升和一致性保证使其成为现代文件共享系统的重要组成部分。

**关键要点（基于 Wireshark 抓包验证）**：
- ✅ LeaseKey 由客户端生成，而不是服务器生成
- ✅ 客户端在 RqLs 上下文中发送 LeaseKey
- ✅ 服务器使用客户端提供的 LeaseKey（不修改）
- ✅ 服务器可以降级或拒绝租约，但不改变 LeaseKey

正确理解和实现租约协议对于构建高性能、可靠的 SMB 服务器和客户端至关重要。开发者应该仔细考虑租约类型的选择、错误处理机制以及安全考虑，以确保系统的稳定性和安全性。
